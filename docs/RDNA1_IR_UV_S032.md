The frontend's `Attribute.cpp` defines this target/index mapping; the normal SPIR-V emitter also transports raw export components as float bits. UV output is separate storage at set 0/binding 2: 136 uint words / 544 bytes, data words 2–129, count 132, status 133, guards 0/1/130/131/134/135. Lane i writes xy to words `2+2*i` and `3+2*i`, only when i is within allocated vertices and the IR predicate is active. The finite lane proof rejects any undefined allocated vertex. One uniform workgroup barrier precedes lane-zero UV count/Ok publication; the original geometry count/status publication follows, with geometry status still last. Missing/duplicate/unsupported metadata, malformed types, partial masks and inadequate declared capacity fail with empty binary/assembly. Runtime overflow behavior is not newly implemented or claimed: these are compile-time rejections in a zero-or-three-vertex subset.

`MeshIrUvOracle.h` is independent test code. It reads actual SPIR-V descriptor/type/layout/access/store/control instructions, evaluates the bounded scalar dataflow for all 32 lanes, and compares a complete independently initialized UV snapshot, including untouched guards, unused words, count/status and write multiplicities. It checks publication order and bounds. The existing geometry ABI checker separately checks the original output. This is a restricted offline evaluator, not GPU execution or a general SPIR-V interpreter.
