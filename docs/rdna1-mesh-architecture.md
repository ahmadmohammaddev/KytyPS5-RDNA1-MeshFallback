## Input/output and memory contract

`src/graphics/shader/shader.h:91` ShaderWorkgroupInputInfo holds threads, LDS/scratch and host/guest subgroup widths. `:99` ShaderMeshInputInfo adds topology, group sizes, output maxima, provoking vertex and split_groups. `:147` ShaderVertexInputInfo joins resource/fetch/stage and clip state; `:212` ShaderPixelInputInfo describes fragment inputs. `src/graphics/shader/recompiler/ir/ShaderIR.h:153` ExportInfo, `:367` StageOutput, `:891` Program carry export metadata, output layout and program state. These are logical contracts, not a ready storage-buffer ABI.

No task/payload producer is present in this traced native draw chain: the draw dispatches mesh directly and NGG front/back code is fused. This does not prove all guest shaders lack payload-like behavior; task/amplification semantics are outside the first prototype.

Synchronization findings:

- `spirvEmitterFlow.cpp:758` EmitBarrier emits workgroup control/memory synchronization (LDS semantics); `spirvEmitterMesh.cpp:202` uses it before shared allocation/output finalization. It cannot synchronize separate workgroups or replace a command-level dependency.
- `src/graphics/host_gpu/renderer/pipeline/shaderResourceBarrier.cpp:51` MakeShaderWriteDependency includes vertex/index/indirect reads; `:153` ShaderWriteBarrier targets compute/all graphics/transfer. Stage masks include mesh only when enabled. A compute output path must explicitly target its actual storage/vertex/index/indirect consumers, without unsupported mesh stages.
- `renderDraw.cpp:4201` records indirect conversion before rendering; `:4292` describes BeginRendering barrier flush; `:4401` explains dependencies outside dynamic rendering; `:4588` handles shader writes. Integrating compute inside an active rendering instance without ending it is unsafe for this design.
- `src/graphics/host_gpu/renderer/meshIndirect.cpp:225` onward Converter::Record ends rendering and orders earlier writes before compute; `:281` orders compute output before indirect/mesh/host reads. Ring slot invalidation/readback follows completion. This is an argument converter, NOT mesh geometry emulation; it still issues drawMeshTasksIndirectEXT at renderDraw.cpp:4479.
- Preserve guest resource residency, BDA/address translation, storage descriptor bounds, scratch/LDS sizing, submission completion and deferred destruction. Shader output buffers must remain live until their final GPU consumer completes; mapped readback requires completion plus invalidation where noncoherent. No assumption of queue ownership transfer or cross-queue safety is justified by this audit.

## Smallest independent compute prototype (proposed, not implemented)

One standalone synthetic Vulkan integration case, no emulator/game startup: dispatch ONE workgroup producing exactly three homogeneous float4 positions, three uint32 indices (0,1,2), vertex_count=3, primitive_count=1, and status in fixed-capacity storage buffers. Use authored public synthetic data; fixed slots avoid compaction/atomics. Initialize guard words and include zero-output and overflow cases with explicit error status; reject insufficient capacity without out-of-bounds writes. No textures, varyings, instancing, restart, guest BDA, indirect draw, multiple groups or game shaders initially.

First gate is buffer correctness, not rendering: validate the compute SPIR-V for Vulkan 1.3; execute with core and synchronization validation; order transfer initialization -> compute storage reads/writes -> transfer readback -> host read, wait for completion and invalidate mapped memory as needed; assert exact counts/indices, position values and unchanged guards. Record physical device/driver and diagnostics; unavailable Vulkan is a skip, never a pass. Intel results are Intel only; repeat on RX 5700 XT independently. No extension spoofing or CPU-generated replacement output in the GPU test.

A later conventional vertex/index draw can consume these buffers with compute-write -> vertex/index-read dependencies and a simple fragment stage, but that is a separate gate. Neither stage establishes PS5 mesh compatibility. The subsequent translation feasibility experiment must feed the existing NGG prologue, MeshAllocate and masked exports through an isolated compute lowering, compare expected outputs, then expand wave/LDS/primitive/culling/fragment semantics deliberately.

Recommended eventual split: preserve logical guest Mesh IR, add explicit compute output lowering around module/output/entrypoint emission, select a separate backend and cache key before FinishMeshStage, and add output-resource scheduling before BeginRendering in ExecutePreparedDraw. Do not redirect all native mesh programs or relax host limits globally. This is a design hypothesis requiring P2/P3 evidence.
